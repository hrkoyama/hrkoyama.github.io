# アトラスの問題・固定ケース・ソースID

`catalog/atlas-identities.json` は、現行の問題・登録済み固定ケース・科学ソースを追跡する外部対応台帳です。
既存の問題ID・URL・配布日・コード・ZIP・入力・参照値・公差・成功／失敗記録は変更していません。
既存ソースに対するIDの付与は**外部対応台帳（sidecar）**で行います。
新しい科学計算・収束試験を実行したという意味ではありません。

## 現行対象への展開

2026-11-27の展開対象は、正本の**174問題・181ケース登録単位・84実装単位**です。合計439 ID、440改訂レコードです。既存の8 IDと改訂 `00` は内容を変えずに保持しています。

- P：`catalog/atlas-test-problems.json` の全174問題。登録されたCがない37問題も、既存の保存結果・説明を保持します。Cがないことを「未実装」や「reading-only」へ読み替えません。
- C：補助配布の159ケースと共通実行例22件。問題との対応が明示的にnullの診断5件はP参照を空にし、問題を作り足しません。
- S：共有配布82単位と、単独で配信されるKEEP・波動発展の数値解析コード2単位。現行ZIP83版と単独解析2版を、計85版として固定します。

共通コード `NMA-S-000012` の並存する2026-11-21/22版は、実際の派生関係と配布ソースの差分を確認して `00/01` に対応付けました。これは今回初めてID管理へ採用した2状態であり、過去にこのIDが使われていたという記録ではありません。
例えば共通移流 `NMA-C-000004@00` は `NMA-P-000001@00` と `NMA-S-000012@01`、Barnes–Hutの共通例は同じSの旧版 `@00` を参照します。単独解析は `NMA-S-000016@00` と `NMA-S-000017@00` で、存在しないZIPを作ったことにはしません。

配布元の正本は `catalog/atlas-identity-sources.json`。既存97 ZIPを、現行83・保存旧版/実験13・技能配布1へ全件分類します。保存旧版を現在の実装として数えたり、過去のNMA改訂を推測で付けたりしません。元のZIP、コード、入力、参照値、成功・失敗・skip記録は保持します。
サイトの表示用frontendやビルド基盤、正本の問題台帳へ未登録の本文中の演習は、このP/C/S件数へ混ぜません。

## 命名と更新

- 恒久IDは `NMA-P-000001`（問題）、`NMA-C-000001`（固定ケース）、`NMA-S-000001`（実装）。
  連番は種類ごとの10進数・最低6桁。分野・章・言語・ファイル名を埋め込みません。
- 改訂は別属性 `revision`。表示は `ID@revision`。大文字16進数・最低2桁で、
  `00 → 01 → … → 0F → 10 → … → FF → 100`。折り返し・再利用はしません。
- `allocation` は**次に発行する番号**です。現行の次番号はP=175、C=182、S=85です。
  廃止したIDも履歴から削除しません。旧名 `legacy_ids` は恒久IDとの対応として保持します。
- Pの問題文・数式・意味を持つ翻訳を訂正したらPを改訂。独立した数学的課題への拡張は新Pです。
- Cの誤った入力・参照・受入条件を訂正したらCを改訂。比較用に併存する別条件は新Cです。
  公差変更は理由とレビューが必要で、合格を得る目的で緩めません。旧条件・結果を保持します。
- Sのバグ修正・性能改善・依存・配布ソース中のコメントを変えたらSを改訂。
  別言語／独立保守する別実装には新Sを付けます。共有実装は問題ごとに複製しません。
- 画面装飾・索引再生成・内容不変のファイル移動だけでは科学版を更新しません。
  ただし台帳が参照する旧パスは保持し、移動先を追加するだけで旧版のbindingを書き換えません。
- 改訂は固定・レビューする単位で進めます。作業中の保存・Gitコミットごとには進めません。

現在の正本問題レコード全体を `catalog/identity-snapshots/ID/00.json` へ凍結しています。
現行P版と正本は既存の問題IDで照合するため、正本配列の並び替えだけでは改訂不要です。
説明・evidenceの内容が変われば変更を保守的に検出します。将来より細かな射影に分ける場合も旧 `00` を書き換えず新改訂にします。
共通22例の外部定義・合格条件・参照説明も、それぞれのC改訂の同ディレクトリーへ凍結します。可変の正本配列の位置を、旧C改訂の保存先として使い続けません。

## 対応台帳と内容ハッシュ

- `catalog/atlas-identities.json`：現行ID、旧ID、改訂履歴、正確なP/S版参照と内容binding。
- `catalog/atlas-identity-history.json`：初回pilotの8ID・全 `00` の変更禁止スナップショット。
  新改訂は現行台帳へ追記し、この初回履歴は更新しません。Node検査が履歴のSHA-256も固定します。
- `catalog/atlas-identity-expansion-history.json`：今回採用した439 ID・440版の変更禁止チェックポイント。検査器とNode検査の両方でSHA-256を固定します。
- `catalog/atlas-identity-sources.json`：現行の正本配布との照合、単独解析、既存97 ZIPの区分。新しい未分類ZIPや未登録の単独解析を検出します。
- `catalog/identity-source-manifests/`：ZIP内だけにある基礎教材・RKDGソースの外部member一覧。元の配布manifestやZIPを後から編集したものではありません。
- `catalog/identity-snapshots/`：改訂ごとの不変な問題レコードと共通C定義。旧版の検証が可変の正本配列に依存しないようにします。
- `catalog/schemas/atlas-identities.schema.json`：編集用JSON Schema。
  実行時はPython標準ライブラリの検査器が構造と相互参照・ファイル内容を確認します。

bindingの `path` はリポジトリルートからの相対POSIXパスです。`pointer` がなければファイルの生バイト列をSHA-256化します。
`pointer` がある場合はRFC 6901で指定したJSON断片を、
`json.dumps(value, ensure_ascii=False, sort_keys=True, separators=(',', ':'), allow_nan=False)`
でUTF-8に変換してSHA-256化します。空文字のpointerはJSON全体です。
重複キー、非有限数、不正なpointer、パス逸脱は受け付けません。
`member` を持つbindingは、`path` のZIP内の正確な通常ファイル名の生バイト列をSHA-256化します。`member` と`pointer`は併用しません。展開せずに読み、重複名・危険パス・symlink等は拒否します。

Cには入力・合格条件・解析参照の式／検証説明・保存結果・保存検証レシートを含めます。
Sにはソース・依存・source manifest・ZIPを含めます。ZIPの選択ソースとの整合性も読み取りだけで確認します。
文献の外部ページを新たに取得・監査したことは意味しません。

通常のSは不変の配布パッケージ単位です。単独解析2件では実在するソース・依存記録・配列形式manifestを結び、archiveを捏造しません。標準ライブラリだけの教材に、存在しない外部依存やrequirementsを付け足しません。
Cの入力・受入条件等はsource manifestとZIP内の実ファイルへ照合します。新しい補助Cは共有inputs/acceptance全体を保守的に固定し、保存入力SHAがある場合は正確に一致するケース入力も結びます。
共通Cの台帳内条件と保存集約レシートは例外として正確なbindingだけを許し、元の取得台帳・ケース・配布ZIP/manifestのSHAと照合します。
同じS版を参照したまま、同じCの数値契約だけを別のものへ差し替えることは拒否します。
契約を直した配布物には新しいS版も必要です。新しい契約の科学的な妥当性は別途レビュー・検証する必要があります。

## 確認コマンド

この作業コピーのルートで実行します。Python標準ライブラリとNode.jsだけを使い、NumPy・SciPyやネットワークは不要です。

```sh
python3 -B scripts/check-atlas-identities.py
python3 -B scripts/build-atlas-identities.py --check
node --test scripts/atlas-identities.test.mjs
git diff --check
```

機械可読の確認結果を作業コピー外へ保存する場合：

```sh
python3 -B scripts/check-atlas-identities.py --report /absolute/private/output/identity-check.json
```

次回以降は、変更前の承認済み台帳も別途指定して差分を確認します。
初回履歴に加え、直前の承認済み版からの削除・再採番・既存改訂の書換えを拒否するためです。

```sh
python3 -B scripts/check-atlas-identities.py --baseline /absolute/private/input/previous-registry.json
```

テストは不正ID・重複・網羅性不足・参照切れ・余分な問題/ソース参照・ファイル改変・危険なZIP名・履歴書換え等の拒否を確認します。
既存の `Public site checks` に検査コマンドを追加し、Node側の回帰検査も既存の全 `*.test.mjs` 実行に含めます。
新しいworkflow・定期処理は追加しません。
push/PRのCIではイベントの変更前SHAの台帳も `--baseline-ref` で照合します。
初回導入で変更前コミットに台帳が存在しない場合だけ、初回履歴を基準にします。
現在の検査器は、手動でも初回pilotと全体展開の2つの不変チェックポイントを必ず照合します。公開前には上記の承認済み台帳照合も行います。

新しい対象の候補作成には `python3 -B scripts/build-atlas-identities.py --write` を使えます。既存レコードは保持し、新規採番と新しいsnapshotの差分をレビューします。既存P/Cの意味を変える訂正は自動上書きせず、明示的に新改訂を作ります。
チェックポイントは後の可変台帳から再生成しません。新たに現行対象から外すS版は、承認済みの不変履歴と照合できるよう、チェックポイントの追記とSHA固定を併せてレビューします。

## 検証の意味と公開前の境界

今回の検査は**保存物の整合性照合**です。数値計算の再実行・公差の再評価・詳細収束検証とは区別します。
初回pilotに記載したSEM/FRの保存25 testsは2ケースの群全体、量子の保存18 testsは7ケースの群全体の記録です。
今回の新しい数値テスト件数として数えません。旧版の合格を別のP/C/S版へ自動継承しません。
通常の補助配布Linux全追試の範囲は69群・159ケースです。C181件の残る共通22例は別の検証範囲であり、保存物・既存の集約レシートを照合しただけで「新たに22例を実行した」とは記録しません。
共通配布に保存されたpytest skipや未達目標も保持します。検証器を変えた今回の公開では既存の全追試を実施し、以後は[Linux追試の実行条件](atlas-depth-ci-scope.md)に従います。
新しい実行レシートを作るときは正確な `P@rev / C@rev / S@rev`、環境、対象ハッシュを記録します。

公開済みのソース・ZIPへIDコメントを後挿入しません。今後の新規配布版では、例えばソース先頭へ
`# atlas-source: NMA-S-000001@01` と書き、具体的なP版やC版の組合せは台帳・実行レシートで固定できます。
ファイル自身のハッシュは外部manifestに置き、自己参照を避けます。

AI学習・評価への分割では、同じPの改訂・翻訳・関連実装・類似派生をまとめて扱います。
管理IDをプロンプトへ出すかは別に制御し、IDの存在だけで重複除去や評価の独立性を保証しません。

この展開でも既存の科学配布・問題ページを保持し、外部台帳・検査器・保守文書だけを追加・更新します。
今後の更新を公開する際も、最新のHR mainとの差分と不変配布を再照合し、MAINTENANCE.mdの候補CI・公開手順を適用します。
ローカルの整合性検査、候補SHAのGitHub全CI、Linux実行、実配信確認は、実際に確認した範囲を区別して記録します。
