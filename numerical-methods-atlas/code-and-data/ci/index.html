公開配布物のLinux再実行

新しいLinuxジョブとPython仮想環境で、公開配布物の取得・依存関係の導入から、代表15問題の実行と数値条件の照合までを確認します。計算コード・入力・参照データは公開サイトの配布物を使います。

保存済みのLinux成功記録はまだありません。初回の成功記録を確認してから、日時・環境・ハッシュ付きのJSONを追加します。最新の実行結果は上のActionsリンクで確認できます。

何を確認するか・運用の条件

現在の対象は15問題、共有を除く14コマンド、3つの配布ZIPです。

水素型原子とHeは同じ1回の実行を共有し、各問題の条件を別々に判定します。Heは保存済みの有限基底PySCF参照と比較します。

  1. 公開配布物の取得・ハッシュ照合
  2. 新規環境への依存導入
  3. 固定入力の計算
  4. 数値条件と出力の判定

取得・導入・実行・数値判定のどこで止まったかを記録します。計算が未実行の場合は、数値条件の不合格と区別します。失敗時のログとJSONもActionsのartifactに残します。

数値判定は固定入力と既存の許容条件に対して行います。ZIPや入力はハッシュで照合しますが、再計算したCSV/画像のバイト一致を要求する検査ではありません。同梱pytestの全検査、アトラス全60問題、独立PySCF参照の再生成は別の確認です。

Public-distribution checks on Linux

A fresh Linux job and Python virtual environment check public distributions from download and dependency installation through execution and numerical acceptance for 15 representative problems. Scientific code, inputs and reference data come from the public-site distributions.

Verification scope and operation

The current scope is 15 problems, 14 distinct commands and 3 distribution ZIPs.

Hydrogenic atoms and helium share one execution and receive separate numerical decisions. Helium is compared with the saved finite-basis PySCF reference.

  1. Public download and hash checks
  2. Fresh-environment dependency installation
  3. Fixed-input execution
  4. Numerical acceptance and output checks

The record distinguishes download, setup, execution and numerical-validation failures. An unrun calculation is separate from failed numerical acceptance. Failure logs and JSON are also retained as Actions artifacts.

Numerical acceptance uses fixed inputs and the existing tolerances. ZIP/input hashes are checked, but rerun CSVs/images are not required to be byte-identical. Full packaged pytest suites, all 60 atlas problems and regeneration of independent PySCF references are separate checks.
