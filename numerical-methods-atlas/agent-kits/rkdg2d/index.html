macOS / Linuxの例です。既存ファイルのない作業フォルダで実行し、Python環境は案内の対応条件に合わせます。Windows等では、その環境に対応する取得・SHA256・Pythonの操作へ読み替えます。

検証を段階的に進める

  1. クイック実計算

    小さな斜め波を実際に解き、厳密解との誤差と保存則を確認します。

  2. 保存結果を再判定

    配布物全体のハッシュを照合し、元48ケースの指標と波形4診断を再評価します。PDEの再実行とは分けて報告します。

  3. 全固定入力で再計算

    斜めエントロピー波、x/yのSod・Shu–Osher、Double Mach、時間刻みの計算と負例を実行し、独立参照・固定基準へ渡します。実行時間は機種に依存します。

  4. 自分のコードを評価

    検証済み候補を別の場所へ複製して改修。Python候補は--solverで指定し、移植・MPIは共通出力契約へ接続します。基準・参照・既存記録は変更しません。

コマンド、JSONの合否、ソースSHA、未実施の項目をまとめる報告様式はMarkdownとmanifestを参照してください。反転xの追加試験は元の候補SHAに固定した別試験です。

既知の結果と限界

公開候補は元48科学ケースと波形4診断に合格。追加の反転対称性試験は6件中5件が合格し、Shu–Osher p3は規格化最大差1.4833×10⁻¹⁰が固定上限1×10⁻¹⁰を超えて不合格です。失敗を含めて配布します。

x/yの厳密1D入力は解析的な1D縮約を使用。斜め波とDouble Machが完全2D結合を確認します。正値性は指定した求積点・面・頂点の範囲です。衝撃波の全域で2・3・4次精度を主張しません。

C++17の解析多項式I/Oと1/2/4分割の保存出力は確認済み。実MPI起動や他言語PDEソルバーの実行は未実施です。共通22実行例とは別の開発キットで、サイト全体の問題・手法件数へ追加していません。

Choose the verification depth

  1. Fresh quick calculation

    Actually evolve a small oblique wave and check analytic error and conservation.

  2. Recheck the stored results

    Verify the complete file hashes and reassess the original 48-case metrics and four waveform diagnostics. Report this separately from fresh PDE execution.

  3. Rerun the full fixed inputs

    Run oblique entropy waves, x/y Sod and Shu–Osher, Double Mach, time refinement and the negative control, then apply independent references and frozen criteria. Runtime depends on the machine.

  4. Evaluate your modified code

    Copy the accepted candidate before editing. Select a Python candidate with --solver; connect language ports and MPI output through the interchange contract. Keep the criteria, references and historical records unchanged.

The Markdown and manifest specify commands, JSON acceptance, source hashes and reporting of unperformed checks. The additional reversed-x test is a separate check pinned to the original candidate SHA.

Known results and limits

The published candidate passes the original 48 scientific cases and four waveform diagnostics. The additional reflection test passes five of six; Shu–Osher p3 fails because the normalized maximum difference, 1.4833e-10, exceeds the frozen 1e-10 limit. The failure is included in the kit.

Exactly 1D x/y inputs use an analytic 1D restriction. Oblique waves and Double Mach exercise full 2D coupling. Positivity is checked at specified quadrature, face and corner points. No global second/third/fourth-order accuracy is claimed across shocks.

C++17 analytic-polynomial I/O and stored 1/2/4-partition fixtures were checked. Real MPI execution and foreign-language PDE solvers have not been run. This development kit is separate from the 22 shared recipes and does not add to the site-wide problem/method counts.
