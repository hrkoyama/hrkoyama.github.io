Approximation and the sources of error

Learning goal: Distinguish absolute and relative error, roundoff, truncation, and iteration error; do not confuse displayed digits with accuracy.

The number of digits returned by a computer is not the number of correct digits. First separate what is being approximated from the stage at which error enters. Approximating a function on a grid and performing arithmetic with finitely many digits introduce error for different reasons.

Replacing a derivative with a difference suggests that a smaller spacing should improve the approximation. However, subtracting nearby numbers loses significant digits. With very small spacing, division by that spacing amplifies roundoff.

Absolute and relative error

Let u be the reference value and U the computed value. Absolute error measures their distance. Relative error divides this distance by the magnitude of the reference value, but becomes a poor indicator near a zero reference. In that case, also report an error normalized by a representative problem scale.

Keep three sources of error separate

Distinguish truncation error from discretization, roundoff from arithmetic, and the error caused by stopping an iteration. Uncertainty in the physical model or input data is another issue. Reducing an iterative residual alone does not remove coarse-grid error.

What happens when the spacing is halved?

For a smooth sine function, the truncation error of the centered difference decreases quadratically with the spacing. The roundoff contribution is roughly machine precision divided by the spacing. Their competition produces the bottom of the error curve.

A small worked example

At x=1, use cos 1 as the reference. First check the order with h=0.2,0.1,0.05,0.025, and then reduce the spacing through negative powers of 10.

Instead of choosing the smallest h, identify where the error curve changes from decreasing to increasing. The best spacing observed here changes with the function and the arithmetic precision.

from math import sin, cos
x = 1.0
for k in range(1, 17):
    h = 10.0**(-k)
    d = (sin(x+h)-sin(x-h))/(2*h)
    print(h, abs(d-cos(x)))

The saved data approach second order for the sufficiently large-spacing sequence, while the error grows again at extremely small spacings. The best spacing and the final roundoff digits can vary slightly between environments.

Review questions and answers

Question 1: Can relative error be evaluated directly where the true value is 0?

Show answer

No: division by zero is undefined. Use absolute error or normalize by a nonzero representative scale for the problem.

Question 2: If error grows as the spacing decreases, must the stated order of the difference formula be wrong?

Show answer

No. The calculation may have moved from a truncation-dominated range into a roundoff-dominated range.

Common pitfalls

  • Do not call displayed digits correct digits.
  • Do not infer convergence order from one spacing.

Key points

  • Separate the sources of error.
  • A smaller step is not always better.
